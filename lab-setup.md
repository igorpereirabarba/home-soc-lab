# Lab Setup

## Overview

This document describes the architecture and configuration of the Home SOC Lab.

The environment was created to practice security monitoring, endpoint telemetry, Windows log analysis, SIEM investigation, and threat detection.

---

# Lab Architecture

```text
Kali Linux VM
      |
      | Authorized Security Testing
      v
Windows 11 VM
      |
      | Windows Security Logs
      | Sysmon Telemetry
      v
Splunk Universal Forwarder
      |
      | Forwarded Logs
      v
Ubuntu Laptop
      |
      | Splunk Enterprise
      v
Search / Detection / Investigation
```

---

# Ubuntu SIEM Host

The physical Ubuntu laptop hosts Splunk Enterprise.

It serves as the central security monitoring system for the lab.

Responsibilities include:

- Running Splunk Enterprise
- Receiving Windows logs
- Receiving Sysmon telemetry
- Storing security events
- Running SPL searches
- Supporting security investigations
- Developing detection logic

---

# Virtualization Platform

Oracle VirtualBox is used to host the virtual systems in the lab.

Current virtual machines:

- Windows 11 VM
- Kali Linux VM

The virtual machines communicate across the lab network so authorized activity generated by Kali can be observed from the Windows endpoint and analyzed using Splunk.

---

# Windows Endpoint

The Windows 11 VM is the primary monitored endpoint.

Hostname:

```text
SOC-Windows
```

The endpoint generates:

- Windows Security Logs
- Authentication activity
- Sysmon telemetry
- Network connection telemetry

---

# Kali Linux Testing VM

The Kali Linux VM is used only for authorized security testing inside the lab.

Current uses include:

- Network reconnaissance
- Port scanning
- Service discovery
- SMB authentication testing
- Controlled failed authentication attempts

The purpose of this VM is to generate activity that can then be analyzed from the defensive SOC perspective.

---

# Sysmon

Sysmon is installed on the Windows endpoint.

It provides additional endpoint telemetry beyond standard Windows event logging.

The current lab uses Sysmon Event ID 3 to monitor network connections.

Example search:

```spl
index=main host="SOC-Windows"
source="WinEventLog:Microsoft-Windows-Sysmon/Operational"
"<EventID>3</EventID>"
```

---

# Splunk Universal Forwarder

The Splunk Universal Forwarder is installed on the Windows VM.

Its purpose is to send security telemetry from Windows to Splunk Enterprise running on Ubuntu.

Current forwarded log sources include:

```text
WinEventLog:Security
```

and:

```text
WinEventLog:Microsoft-Windows-Sysmon/Operational
```

---

# Splunk Enterprise

Splunk Enterprise is installed on the Ubuntu laptop.

Current uses include:

- Searching Windows Security events
- Searching Sysmon events
- Investigating authentication failures
- Identifying source IP addresses
- Grouping activity by account
- Building threshold-based detections
- Supporting incident investigation

# Failed Authentication Detection Lab

A local Windows test account named:

```text
socuser
```

was created for authentication testing.

Controlled failed SMB authentication attempts were generated from the Kali Linux VM against the Windows endpoint.

Windows recorded these attempts as:

```text
Event ID 4625
```

The events were forwarded into Splunk Enterprise.

---

# Initial Failed Logon Search

```spl
index=main host="SOC-Windows"
source="WinEventLog:Security"
EventCode=4625
earliest=-30m
```

This confirmed that Splunk had successfully ingested the failed authentication events.

---

# Authentication Analysis

The events were grouped by username and source IP address:

```spl
index=main host="SOC-Windows"
source="WinEventLog:Security"
EventCode=4625
earliest=-30m
| stats count by Account_Name, Source_Network_Address
```

Observed result:

```text
Account_Name: socuser
Source_Network_Address: 192.168.50.10
Count: 5
```

---

# Detection Logic

A detection threshold was added:

```spl
index=main host="SOC-Windows"
source="WinEventLog:Security"
EventCode=4625
earliest=-30m
| stats count by Account_Name, Source_Network_Address
| where count >= 5
```

The detection successfully identified repeated failed authentication attempts from the Kali Linux VM.
